## 一、项目定位

从固定屏幕的像素风关卡制游戏，重构为**有界大地图 .io 风格的休闲竞技淘汰赛**。保留 FC《气球大战》的核心踩气球乐趣，但利用现代移动设备能力实现高清扁平卡通视觉和大地图自由飞行。

**核心体验一句话**：在一张天空大地图上，带着气球飞行，踩爆别人的气球壮大自己，最后存活者获胜。

## 二、世界与地图

### 2.1 地图尺寸

固定有界地图，世界尺寸 2400×1800。可视区域竖屏约 720×1280（9:16），横屏约 1280×720（16:9）。玩家始终在屏幕中心偏下位置。两种横竖屏模式下世界坐标和地图尺寸不变，仅可视区域宽高比随屏幕旋转切换。

### 2.2 相机系统

相机平滑跟随玩家（lerp 系数 0.1），靠近地图边缘时停推（边界钳制），不露出地图外空白。上方视野略多于下方（玩家位于屏幕中心偏下约 1/3 处），方便观察追击者。相机缩放固定，不随气球数变化——保持视野一致性，避免晕眩。

边缘钳制时玩家位置可能偏离屏幕偏下点，不影响操控。横竖屏切换时保持世界坐标不变，重新计算可视区域和 HUD 布局。

### 2.3 空间分区

地图划分为 120×120 的网格单元（20×15 = 300 格）。碰撞检测只查同格及相邻 8 格，为 16-24 实体留有余量。

### 2.4 地图边界

边界用半透明蓝白色气流墙呈现，碰到柔和反弹。比硬墙自然，视觉上暗示世界有限。

### 2.5 地图内容物

**云岛平台**（约 15-20 个散布全图）：可着陆的浮空平台，造型为立体云朵（圆角白色+柔和阴影底面）。本游戏中云岛平台是唯一的固体着陆面，没有单独的地面层——下文提及"平台/地面"均指云岛平台。

**小白云/闪电云**（3-5 个）：详见第六节闪电云系统。

**气流区**：方向性风场，进入后推动角色位移。用流动粒子线标识方向，可利用加速也可被扰移。

**水域**：地图底部边缘的水面，半透明蓝绿色+波纹动画。带气球可在水面飞行，完全沉没才死亡。

**鲸鱼**：1 只，水域巡逻。详见第六节鲸鱼系统。

### 2.6 缩圈机制

气流墙随时间向内收缩，迫使剩余玩家集中相遇。前 1 分钟不缩，之后每 30 秒缩一小圈，最后阶段集中在核心区域。

**圈外惩罚**：被缩圈推到圈外的角色会受到持续向内的气流推力（比正常边界反弹更强）。有气球的角色可以主动飞回圈内，不会直接淘汰。如果角色在圈外且 0 气球（无法飞行逃脱），会被气流推入水域导致淘汰。

## 三、核心玩法机制

### 3.1 气球物理

保留气球大战的核心物理——重力 + 拍打冲量 + 终速限制。气球越多重力越小（更轻），拍打越高。

**关键改进**：水平移动从瞬间设速改为加速度模型（`vx += accel * input`，松手后 `vx *= friction`），让飞行有"飘"感而非"走"感。拍打冲量保持瞬时脉冲式，保留节奏感。物理常量以"世界单位/秒"定义，固定步长 1/60s 推进，保证不同帧率下手感一致。

### 3.2 气球成长与风险

| 参数 | 值 |
|------|-----|
| 初始气球 | 2 |
| 硬上限 | 5 |
| 每多 1 个气球 | 体型 +3%，移速 +2% |
| 重力缩放 | 气球越多重力越小，0 气球时最重（坠落快），5 气球时最轻（漂浮感强）。具体曲线待调参 |
| 拍打冲量缩放 | 气球越多拍打冲量越大，0 气球时无法拍打。具体值待调参 |
| 踩踏弹跳 | 攻击方踩踏后弹跳高度 = 当前拍打冲量 × 0.8，可用于连踩 |

多气球 = 更快更灵活但目标更大，容易被发现和追上。风险来自"暴露"而非"变慢"。到 5 个气球时体型约 1.09 倍、移速约 1.06 倍——差异不大但可感知。气球的主要来源是踩踏夺取，不是平台恢复。

### 3.3 踩踏与气球夺取

| 碰撞类型 | 条件 | 结果 |
|---------|------|------|
| **踩踏** | 从上方接触 + 攻击方有气球 + 向下运动 | 被踩方 -1 气球，攻击方 +1 气球（气球转移），攻击方弹跳 |
| **侧面碰撞** | 非从上方接触 | 双方弹开，不损失气球（遵循 FC 原版） |
| **踢杀** | 攻击方有气球 + 被攻方 0 气球 + 在地面/平台 | 被攻方直接淘汰 |

**气球溢出**：攻击方已达到硬上限（5 个气球）时踩踏敌方，被踩方仍失去 1 气球并弹开，但攻击方不获得气球（溢出浪费）。弹跳效果正常触发。

**边界情况**：两个 0 气球角色相遇只能产生侧面碰撞（弹开），无法互相淘汰——所有攻击路径都要求攻击方至少有 1 个气球。这意味着两个在地面上挣扎充气的角色不会互相构成威胁，除非有第三方带着气球来踩。

### 3.4 零气球生存链路（核心机制）

这是区别于"0 气球即淘汰"的关键设计，适用于所有角色（玩家和 AI）：

```
气球被踩光（0 个）
  → 失去浮力，自由坠落
    → 坠落期间可以左右操控方向（瞄准平台），但无法拍打
    → 落到平台/地面 → 进入"地面脆弱态"
        → 可以左右走动
        → 无法跳跃和拍打（没有气球）
        → 静止不动 2 秒 → 触发充气动作（1.5 秒，有动画）
          * "静止"定义：水平输入处于中立且速度低于一个较小阈值。任何移动或输入会重置 2 秒计时。（具体阈值见第十章调参项）
          → 充气期间无人攻击 → 获得 1 气球 → 恢复飞行 → 翻盘继续
          → 充气期间被踩踏 → 淘汰
    → 坠入水域 → 完全沉没 → 淘汰
    → 坠落途中被鲸鱼吞食 → 淘汰
```

**设计意图**：0 气球不是终局，而是充满张力的挣扎求生态。追击方要决策——补刀还是转去打别人。被追方要决策——往哪落、能不能争取到充气时间。平台变成"救命稻草"而非"刷气球点"。

AI 同样遵循此规则——AI 在 0 气球时也会坠落、落地、尝试充气，玩家能看到 AI 也在挣扎，增加大地图的动态戏剧感。

### 3.5 平台恢复规则

仅在气球为 0 时着陆平台才可触发充气恢复至 1 个气球。气球不为 0 时着陆只是休息（可以停手歇一会），不增加气球。避免蹲平台刷气球的策略。

### 3.6 淘汰条件

真正导致淘汰的只有以下情况：

1. **地面脆弱态被踩杀**：0 气球 + 在平台/地面 + 被有气球者踩踏
2. **水域沉没**：0 气球 + 坠入水域 + 完全沉没（带气球时可在水面飞行，不触发死亡）
3. **鲸鱼吞食**：贴水飞行或坠落时被鲸鱼跳出水面吃掉（随机事件，详见第六节）
4. **闪电击中**：被闪电云发出的闪电击中 → 触电坠落 → 无翻盘机会，直接淘汰

注意：闪电击中与其他淘汰路径的关键区别——被踩爆气球到 0 可以坠落→落平台→充气翻盘，但被闪电击中是触电坠落、无法翻盘、直接淘汰。闪电是比踩踏更致命的威胁。

## 四、对局流程

### 4.1 局结构

淘汰生存赛（Battle Royale）。进入游戏 → 倒计时 3 秒 → 所有气球战士从地图边缘不同位置入场，各持 2 个气球 → 自由飞行对战 → 被淘汰即出局，不可重生 → 最后存活者胜利 → 显示结算 → 可立即开始下一局。

### 4.2 动态节奏

随淘汰进行，气流墙逐步向内收缩（缩圈），迫使剩余玩家集中相遇。缩圈节奏：前 1 分钟不缩，之后每 30 秒缩一小圈，最后阶段集中在核心区域。

### 4.3 结算信息

排名、淘汰数、最大气球数、存活时长。

### 4.4 AI 补充规则

被淘汰的 AI 不重生。前期（前 30 秒内）被淘汰的 AI 允许以 1 气球状态重新入场一次（"复活赛"机制），维持前期密度感，之后不再复活。此细节可在实施时调整。

## 五、实体系统与 AI

### 5.1 实体类型

| 实体 | 数量 | 说明 |
|------|------|------|
| 玩家 | 1 | 由人操控 |
| AI 气球战士 | 15-23 | 4 种性格类型，详见下表 |
| 云岛平台 | 15-20 | 散布全图，可着陆 |
| 小白云 | 3-5 | 发出闪电的环境危险物 |
| 鲸鱼 | 1 | 水域巡逻，随机吞食 |
| 气流区 | 若干 | 方向性风场 |

### 5.2 AI 气球战士类型

| 类型 | 占比 | 行为 | 特点 |
|------|------|------|------|
| **飘游型** | ~40% | 低速随机飘浮，偶尔拍打，不主动追击 | 容易踩，地图"基础猎物"，给玩家成就感 |
| **追击型** | ~25% | 中速追踪最近目标，尝试从上方踩踏，会利用气流 | 主要威胁 |
| **伏击型** | ~20% | 常驻平台附近，等目标接近时冲刺踩踏，体型小速度快 | 对在平台充气的角色构成威胁 |
| **暴躁型** | ~15% | 高速大体型，追击距离远，转向慢，踩踏力强 | "Boss"级威胁，但自身大目标易被围攻 |

### 5.3 AI 通用行为

所有 AI 都会：避免触碰闪电和水面；0 气球时主动寻找平台落地充气；被追击时尝试利用气流逃脱。AI 之间也会互相踩踏（增加大地图的动态感和偶然性——玩家可能看到两个 AI 打起来，坐收渔利）。

### 5.4 AI 决策频率

不是每帧决策，而是每 15-30 帧（0.25-0.5 秒）重新评估一次目标和方向。降低 CPU 开销，也让 AI 行为有"反应延迟"，更像真人。

## 六、环境危险系统

### 6.1 闪电云系统

**小白云**是可穿过的无害实体——角色可以穿过去，不阻挡不碰撞。但小白云会在一定时长后随机发出闪电。

**闪电行为**：发出后像弹球一样缓慢移动，碰到云岛平台反弹改变方向，碰到白云本体或海域则消散消失。闪电有有限寿命（消散前存在一段时间）。

**击中效果**：角色被闪电击中 → 触电坠落 → 无翻盘机会，直接淘汰。与被踩爆气球不同（后者可以落平台充气翻盘），闪电击中是无可挽回的致命威胁。

**战术层面**：小白云区域是"高风险高收益"地带——可穿过云层走捷径，但承担被闪电击中风险。多个小白云的闪电弹跳可能交叉覆盖，形成临时禁区。

### 6.2 鲸鱼系统

1 只鲸鱼在水域巡逻。随机事件——鲸鱼会跳出水面吞食贴水飞行或坠落的人物。有预警动画（水面先涌起气泡/漩涡，短暂延迟后鲸鱼跃出）。带气球贴水飞行也有被吃风险，鼓励玩家避免长时间贴水飞行。

### 6.3 气流区

方向性风场区域，进入后推动角色位移。用流动粒子线标识方向和强度。可利用加速追击或逃脱，也可被扰移偏离路线。气流方向和强度可周期性变化。

## 七、视觉风格与渲染

### 7.1 整体风格

现代扁平卡通风格——渐变色块、柔光阴影、圆润线条，清新明快的视觉调性。参考移动端休闲游戏的简约感，不做暗黑系或写实路线。色彩饱和度适中，背景用柔和天空渐变（日间蓝天 + 云层）。

### 7.2 角色视觉

圆润卡通小人——圆头、胖身体、小手小脚。头顶气球用半透明渐变球体绘制（有高光和反光）。拍打时手臂上扬动画，被踩时身体压扁回弹，触电时全身闪烁电弧。不同 AI 类型用不同主色调和装饰区分：飘游型浅色系、追击型暖色、伏击型深色、暴躁型高饱和 + 大体型。

### 7.3 预渲染精灵缓存

每个实体类型在初始化时绘制到离屏 Canvas（包含各动画帧），运行时只做 `drawImage` blit + 变换（缩放/旋转/翻转）。角色动画帧：拍打 4 帧、行走 4 帧、待机 2 帧、坠落 2 帧（0 气球自由落体姿态）、充气 3 帧、触电 2 帧、弹开 1 帧（侧面碰撞后短暂后仰）。预渲染为精灵表。粒子效果用实时绘制（数量少不需缓存）。

### 7.4 背景与地图视觉

天空渐变背景（浅蓝到白），散布蓬松云朵作为视觉装饰层（视差滚动——远层慢、近层快）。云岛平台用立体云朵造型（圆角白色 + 柔和阴影底面）。小白云用白色蓬松云朵 + 内部闪烁电弧预警。水面用半透明蓝绿色 + 波纹动画。气流区用流动粒子线。地图边界气流墙用半透明蓝白色能量场 + 流动粒子。

### 7.5 HUD

半透明毛玻璃风格面板。左上角：气球数（Canvas 绘制气球图标 + 数字）。右上角：剩余人数 + 小地图（半透明圆形/方形，显示实体点）。顶部居中：存活时长。淘汰时显示"你被淘汰了" + 排名 + 最终数据。

## 八、操控方案

### 8.1 触屏操控（主要）

**虚拟摇杆 + 拍打键**：屏幕左半区放置虚拟摇杆（触摸即出现，松手即消失），控制水平方向移动，摇杆推力大小影响加速度。右下角放置大拍打键（80px 圆形），点击即拍打。

横屏时摇杆在左侧、拍打键在右侧底部。竖屏时摇杆在屏幕左下、拍打键在右下。

### 8.2 键盘（桌面测试）

WASD / 方向键控制水平移动，空格/上键拍打。

### 8.3 手柄

左摇杆控制移动，A/B/X/Y 任一键拍打。

### 8.4 暂停

触屏：屏幕右上角放置半透明暂停按钮（⏸ 图标，40px）。键盘：ESC 键。手柄：Start 键。暂停时显示半透明遮罩 + "已暂停" + 继续按钮 + 退出按钮。

### 8.5 设计原则

保留拍打节奏感（核心乐趣），摇杆比方向键更适合大地图的连续飞行操控。没有"向下"控制——靠重力下落。

## 九、技术架构

### 9.1 技术栈与开发路线

#### 两阶段策略

**阶段 A：Web 原型验证** — 用 Vite + 原生 ES Modules + HTML5 Canvas 2D 快速搭建可玩游戏原型，在浏览器和手机浏览器中验证核心玩法手感、视觉风格、操控方案、性能表现。Web 版本是降低试错成本的原型工具，不是最终产品。

**阶段 B：鸿蒙原生 App** — 原型验证通过后，用 ArkTS + ArkUI Canvas 开发鸿蒙原生应用作为正式商业产品。旧版代码和文档全部废弃，仅以本设计规格书和实施计划为唯一信源重新开发。

#### 阶段 A 技术栈

Vite + 原生 ES Modules + HTML5 Canvas 2D。零运行时依赖。固定步长累积器（1/60s），物理和 AI 更新在固定步内执行，渲染用 requestAnimationFrame。

#### 模块可移植性原则

开发阶段 A 时需保持可移植层纯净——游戏逻辑层（config/entities/systems/managers + PhysicsEngine/SpatialGrid/Camera）不得引入任何浏览器 API，使其可直接搬到 ArkTS。渲染层可使用 Canvas 2D API（ArkUI Canvas 基本兼容），但不得直接操作 DOM。输入层和 UI 入口层标记为需重写，开发时保持接口清晰以降低迁移成本。

### 9.2 模块结构

```
src/
├── main.js                        # 入口：初始化、启动
├── config/
│   ├── physics.js                 # 物理参数（重力、加速度、终速等）
│   ├── world.js                   # 地图尺寸、网格大小、缩圈参数
│   ├── entities.js                # 实体配置（AI 类型、属性、颜色）
│   └── visuals.js                 # 视觉参数（颜色、尺寸、动画帧数）
├── engine/
│   ├── GameEngine.js              # 主循环、状态机调度
│   ├── PhysicsEngine.js           # 物理（加速度模型、气球状态影响）
│   ├── Camera.js                  # 相机跟随、边界钳制
│   ├── Renderer.js                # Canvas 渲染主控
│   ├── SpatialGrid.js             # 空间分区碰撞查询

    └── ResultState.js             # 结算画面
```

### 9.3 状态机

`MenuState → PlayState → ResultState → MenuState`。GameEngine 持有当前状态对象，每帧调用 `state.update()` 和 `state.render()`。暂停作为 PlayState 的子状态。

### 9.4 渲染流程

```
每帧：
  1. 状态机 update()（物理、AI、碰撞、缩圈等）
  2. 相机更新（lerp 跟随 + 边界钳制）
  3. 渲染：
     a. 清屏
     b. 背景层（天空渐变 + 远景云层视差）
     c. 世界变换（ctx.translate(-camera.x, -camera.y)）
     d. 地图元素（平台、小白云、气流区、水域、边界）
     e. 实体（敌人 → 玩家，从精灵缓存 blit）
     f. 粒子效果
     g. 还原变换
     h. HUD（屏幕空间，不受相机影响）
```

### 9.5 与旧版的关键技术差异

| 方面 | 旧版 | 新版 |
|------|------|------|
| 坐标系 | 固定屏幕坐标 480×360 | 世界坐标 2400×1800 + 相机变换 |
| 渲染 | 实时 Canvas 绘制 | 预渲染精灵缓存 + blit |
| 物理 | 帧驱动（per fixed step） | 固定步长 + 世界单位/秒常量 |
| 水平移动 | 瞬间设速 `vx = ±2.8` | 加速度模型 `vx += accel * input` |
| 碰撞检测 | 全量两两检查 | 空间网格分区 |
| 屏幕边界 | 硬墙 | 气流墙 + 缩圈 |
| 状态管理 | running + gameOver 布尔值 | 状态机（Menu/Play/Result） |
| 实体数 | 4 敌人 | 16-24 实体 |
| 视觉 | 像素艺术 8px 字体 | 扁平卡通 + 精灵缓存 |
